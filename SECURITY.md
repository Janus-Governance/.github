# Security Policy

## Reporting a vulnerability

Report a suspected vulnerability privately through the **Security** tab of the affected repository when private vulnerability reporting is available. Do not publish vulnerabilities, exploit details, secrets, credentials, or sensitive data in an issue, pull request, discussion, or other public channel.

If private reporting is unavailable, contact an owner of the Janus Governance organization first and request a private reporting path without revealing sensitive details publicly. Do not send vulnerability details to an unverified address.

## Supported scope

Security review covers the current version of `main` and the latest release when a release exists. Janus Governance does not guarantee a response or remediation service level. Reports are assessed according to impact, available evidence, and repository ownership.

## Classification

- A **technical vulnerability** can compromise confidentiality, integrity, availability, authentication, authorization, or another security property.
- A **semantic divergence** is a mismatch between an implementation or document and its governing definitions; report it to the relevant maintainers without exposing sensitive material.
- A **support request** asks for usage or troubleshooting help and should use the repository's ordinary support or issue channel when safe to do so.
