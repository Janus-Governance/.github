# Contributing to Janus Governance

We welcome focused contributions that improve public documentation, specifications, tooling, implementations, tests, and governance clarity within the purpose of the affected repository.

## Before contributing

Open an issue before proposing a normative or architectural change. The issue should identify the problem, affected boundary, intended outcome, and relationship to existing definitions. Requirements that would change Janus normative definitions belong in the [Janus Governance Core](https://github.com/Janus-Governance/janus-governance-core).

Security disclosures must follow [SECURITY.md](SECURITY.md), not the public issue workflow.

## Pull requests

Contribute through a dedicated branch and pull request. Keep changes small, reviewable, and traceable. Identify the change class, affected files, explicit exclusions, provenance, and rollback approach. Maintainers may request that a contribution be split or reduced in scope.

Provide evidence appropriate to the change:

- informational changes: link and terminology checks;
- implementation changes: relevant tests, builds, and behavioral evidence;
- normative or architectural proposals: issue context, rationale, affected definitions, and semantic review;
- publication or deployment changes: pre-publication and post-publication verification.

Passing tests or builds does not by itself prove semantic conformity.

## Protected information

Do not submit secrets, credentials, personal data, sensitive institutional information, private operational material, or private Labs assets. Confirm that all contributed material has appropriate provenance and is authorized for public release.
